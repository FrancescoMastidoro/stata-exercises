# Feedback: Day 7

**Overall**: Strong effort with good Stata instincts, but several tasks contain logical or syntactic errors that produce incorrect results.

## Task-by-task

| Task | Status | Comment |
|------|--------|---------|
| 1. Missing values | PARTIAL | `misstable summarize, all` is correct and good. However, the comment "share of observations missing for wage: 0%" is wrong — `misstable summarize` shows wage has 24 missing observations (~2.9%). The hint explicitly flags this. No manual calculation (e.g. `count if missing(wage)` or `summarize missing(wage)`) was performed to confirm. |
| 2. Impossible values | PARTIAL | `summarize hours` and `summarize ttl_exp` are correct. However, the `list` command syntax is wrong: `list in 1/10 if hours < 15` combines an `in` range with an `if` condition, which is valid Stata syntax but almost certainly not the intent — it only looks at the first 10 observations, not all observations meeting the condition. Should be `list if hours < 15 \| hours > 40` without the `in` qualifier. The substantive thresholds chosen (hours < 15, ttl_exp < 5) are also debatable as "impossible" rather than merely unusual; hours > 168 would be a true impossibility. |
| 3. Labelled categorical variable | PARTIAL | `tabulate race`, `numlabel _all, add`, and the second `tabulate race` are all correct. However, the interpretation of `summarize race` is flawed: the comment claims the mean "is informative about the relative frequency of each race" — this is incorrect reasoning. The mean of an arbitrarily coded categorical variable is not meaningfully interpretable regardless of its value. The task asks whether treating a categorical as numeric produces a *meaningful* mean; the answer should be no, but Francesco argues yes. |
| 4. Cross-check missingness | PASS | `tabulate south` and `tabulate south, missing` are correct, and the comparison is noted. The `gen flag_miss` + `tabstat wage, by(flag_miss) stat(mean n)` approach is a reasonable workaround for the union-missingness comparison and the interpretation is sound. |
| Bonus | PASS | Correctly generates `flag_problem` and identifies the Stata missing-value-as-large-number issue, which is a non-trivial insight for a beginner. The fix would be `gen flag_problem = missing(wage) \| (hours > 168 & !missing(hours))`, but the diagnosis of the problem is accurate. |

## What to work on

For Task 2, remove the `in 1/10` qualifier from your `list` commands — it silently restricts results to the first 10 rows and will miss most problematic observations; `list if hours > 80` alone is sufficient. For Task 3, revisit what "meaningful mean" means for a categorical variable: the numeric codes assigned to race categories (1, 2, 3) are arbitrary labels, so averaging them produces a number with no statistical or economic interpretation regardless of what that number happens to be. For Task 1, always verify your own claims with code — `count if missing(wage)` would have immediately shown the comment "0% missing" was wrong.
